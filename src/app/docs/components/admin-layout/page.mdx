# Admin Layout Components

This section covers the structural layout components of the Kinetic Admin Portal, including the navigation shell, role toggles, and search filters.

---


## Overview

This page provides an overview and technical specifications for the Admin Layout Components subsystem within the Kinetic Platform.

## 1. Sidebar Navigation

The admin `Sidebar` component displays main panel categories, handles routing, and processes signOut triggers.

### Purpose
To provide persistent, responsive navigation across administrative screens (Dashboard, Questions Directory, Content Editor, Users, Analytics, Settings), reflecting access changes based on the user's role.

### Location in Codebase
- File: [src/components/admin/Sidebar.tsx](file:///Users/vaishu/Downloads/Base_Project/src/components/admin/Sidebar.tsx)

### Props Interface
```typescript
interface SidebarProps {
  activeId: string;                    // ID of the currently selected sidebar item (matches store keys).
  onSelectTab?: (id: string) => void;  // Callback fired when a tab button is clicked.
  userRole?: 'admin' | 'editor';      // Visual access role toggle restricting menu displays.
}
```

### State Management
- Internally consumes the Supabase Client Auth object (`createClient()`) to trigger sign-out flows on log-out buttons.
- Filter operations run conditionally based on `userRole`: `editor` accounts only see the Content Editor (`'editor'`) and Logout (`'logout'`) tabs.

### API & Database Dependencies
- **Supabase Authentication API**: Triggers `supabase.auth.signOut()` on exit.
- **Cookies**: Deletes local session validation cookies (`aptitude_mock_auth`, `aptitude_onboarding_completed`) on logout.

## 2. Header

The admin `Header` component displays metadata status indices, features a dark/light mode toggle, and includes an interactive client role simulator.

### Purpose
Houses notification centers, theme toggles, profile statistics, and toggles client roles (e.g. previewing the student dashboard vs editing the admin panel).

### Location in Codebase
- File: [src/components/admin/Header.tsx](file:///Users/vaishu/Downloads/Base_Project/src/components/admin/Header.tsx)

### Props Interface
```typescript
interface HeaderProps {
  currentRole: UserRole;                // Current active user object (contains avatar, name, and email).
  onRoleChange: (role: UserRole) => void; // State dispatcher updating role contexts.
}
```

### User Flows (Preview vs. Edit Role Simulator)
1. **Preview Mode (Student view)**:
   - User clicks the **Preview** button.
   - The app populates local storage details: `localStorage.setItem('aptitude_current_role', studentData)`.
   - The header updates role state to `editor` and triggers a Next.js route push to `/student/dashboard`.
2. **Edit Mode (Admin view)**:
   - User clicks the **Edit** button.
   - The app resets role contexts to the default `admin` profile, unlocking editorial configurations.

## 3. Questions Directory (QuestionsManagement)

The central administrative screen aggregating domain filter menus and catalog data tables.

### Purpose
Enables searching, sorting, deleting, and editing questions, resolving visual primary key calculations, and initiating editor overrides.

### Location in Codebase
- Parent Component: [QuestionsManagement.tsx](file:///Users/vaishu/Downloads/Base_Project/src/components/admin/QuestionsManagement.tsx)
- Filter Menu: [FilterDropdowns.tsx](file:///Users/vaishu/Downloads/Base_Project/src/components/admin/directory/FilterDropdowns.tsx)
- Question Registry Table: [QuestionTable.tsx](file:///Users/vaishu/Downloads/Base_Project/src/components/admin/directory/QuestionTable.tsx)

### Props & State Management
- **FilterDropdowns**:
  - `searchQuery` (`string`): Text-input matches tags, stems, or Crockford visual IDs.
  - `selectedDomain` (`string`): Drops down to filter domains. Triggers cascade wipes of sub-topics/concepts.
  - `selectedDifficulty` (`'All' | 'EASY' | 'MEDIUM' | 'HARD'`): Filters difficulty.
  - `selectedStatus` (`'All' | 'Published' | 'Draft' | 'Review Pending'`): Filters publishing states.
- **QuestionTable**:
  - `sortField` (`'id' | 'stem' | 'domain' | 'difficulty' | 'date' | 'status'`): Directs row sorting.
  - `sortOrder` (`'asc' | 'desc'`): Toggles sort direction.
  - `currentPage` (`number`): Track index for paginating sets of 10 rows.

### Alphanumeric Visual Primary Key (Crockford Base32 ID)
The `QuestionTable` maps raw question records to friendly Crockford Binary IDs.
- Calculates domain, subtopic, and concept sequence codes.
- Renders the computed visual key (e.g. `Q-8029-X`) inside a tooltip that provides a detailed breakdown of taxonomical parameters upon hover.
- Features a copy button to instantly copy the ID to the clipboard.
