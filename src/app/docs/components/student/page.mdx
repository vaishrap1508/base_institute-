# Student Portal Screens

This section outlines the primary interfaces through which students interact with the platform, from authentication to onboarding, dashboard progression, and domain course navigation.

---


## Overview

This page provides an overview and technical specifications for the Student Portal Screens subsystem within Base Institute.

## 1. Login Screen

The Login screen manages student and administrator authentication, handling account creation, forgotten passwords, OAuth sign-ins, and developer-oriented sandbox modes.

### Purpose
To authorize user sessions using email/password credentials or Google OAuth, establishing JWT session tokens in browser cookies.

### Location in Codebase
- File: [src/app/login/page.tsx](file:///Users/vaishu/Downloads/Base_Project/src/app/login/page.tsx)

### Props Interface
- None (standard Next.js Page component).

### State Management
- `isRegister` (`boolean`): Toggles interface between "Sign In" and "Sign Up" states.
- `isForgotPassword` (`boolean`): Triggers the forgot password email link reset panel.
- `showPassword` (`boolean`): Shows or hides the password input characters.
- `loading` (`boolean`): Tracks active email/password login or signup async operations.
- `googleLoading` (`boolean`): Tracks social OAuth redirections.
- `errorMsg` (`string | null`): Displays validation errors, authentication failures, or connection alerts.
- `email`, `password`, `confirmPassword`, `fullName`: Tracks string values from input fields.

### API Dependencies
- `/api/auth/sign-in`: Handles user validations.
- `/api/auth/sign-up`: Handles registration validations and sends confirmation triggers.
- `/api/auth/google`: Initiates Google authentication credentials exchange.

### Database Dependencies
- Writes to Supabase Auth tables (`auth.users`, `auth.identities`).
- Trigger functions write initial user row entries into `public.profiles`.

### User Flows
1. **Interactive Form Input**: User types credentials and submits.
2. **Submit Handling**: Frontend validates format (e.g. matching confirm password).
3. **Authentication Handshake**: Invokes standard Supabase signIn / signUp hooks.
4. **Onboarding Routing**: If a new profile is detected, redirects to `/onboarding`. Otherwise, redirects to the student or admin dashboard.

## 2. Onboarding Screen

A step-by-step questionnaire flow that runs on a user's initial login to collect academic and learning targets.

### Purpose
Collect user profile metrics, university context, target preparation timelines, and study topics to customize recommendations.

### Location in Codebase
- File: [src/app/onboarding/page.tsx](file:///Users/vaishu/Downloads/Base_Project/src/app/onboarding/page.tsx)

### Props Interface
- None.

### State Management
- `currentStep` (`number`): Integer tracking the active wizard phase (`1` to `4`).
- `userType` (`'student' | 'other' | ''`): Separates general learners from academic students.
- `username` (`string`): The visual user identifier checked for uniqueness.
- `state`, `college`, `degree`, `branch`, `graduationYear`: Academic registration details.
- `primaryGoals` (`string[]`): High-level prep goals (e.g., placements, mock exams).
- `targetTimeline` (`string`): Timeline preferences.
- `weeklyCommitment` (`string`): Commitment parameters.
- `learningPreferences` (`string[]`): Multi-select study style formats.

### API Dependencies
- `GET /api/user/username-check`: Query to verify username availability.
- `POST /api/user/onboard`: Saves user selections and unlocks the profile.

### Database Dependencies
- `public.profiles` (`username`, `user_type`, `academic_info`).
- `public.student_goals` (`goals`, `timeline`, `commitment`, `preferences`).

## 3. Student Dashboard SPA

A single-page application dashboard aggregating learning metrics, roadmaps, leaderboards, and setting configurations.

### Purpose
Acts as the central user portal displaying streak telemetry, XP achievements, interactive domain tracks, practice rooms, and calendar logs.

### Location in Codebase
- File: [src/app/student/dashboard/page.tsx](file:///Users/vaishu/Downloads/Base_Project/src/app/student/dashboard/page.tsx)

### State Management
- `activeSidebarTab`: Directs the active SPA page render tab (`dashboard`, `learning`, `practice`, `mockTests`, `careerHub`, `leaderboards`, `profile`, `settings`).
- `profile`: Holds user profile data fetched during initialization.
- `solvedCount`, `streak`, `xp`: Visual indicators that sync with profile achievements.
- `completedNodeIds`, `activeNodeId`: Tracks progress nodes on the curriculum path.
- `activeQuestion`: Triggers modal overlays for question-solving interfaces.
- `activeLearningTab`: Manages active tab index inside learning panels.

### API Dependencies
- `GET /api/student/dashboard-stats`: Fetches stats, streaks, and user levels.
- `POST /api/student/save-profile`: Handles updates to profile settings.

### Database Dependencies
- `public.profiles`, `public.user_streaks`, `public.user_xp_logs`.
- `public.question_solutions` (reads student solving sequences).

## 4. Domain / Learning Dashboards

Dynamic portals focused on domain learning paths (e.g., Quant, Verbal, Coding) and question solving pages.

### Purpose
Renders domain structures, concepts trees, question lists, explanation sheets, and pre-renders LaTeX formulas.

### Location in Codebase
- Files: 
  - [src/app/student/domains/page.tsx](file:///Users/vaishu/Downloads/Base_Project/src/app/student/domains/page.tsx) (Main index)
  - [src/app/domain/[domainId]/page.tsx](file:///Users/vaishu/Downloads/Base_Project/src/app/domain/[domainId]/page.tsx) (Dynamic route)

### State Management
- `activeTopic` (`string`): Filters listed sub-topics.
- `selectedDifficulty` (`'easy' | 'medium' | 'hard' | 'all'`): Filters displayed exercises.
- `solvedFilter` (`'all' | 'solved' | 'unsolved'`): Filter criteria.
- `questions` (`Question[]`): Active array of question objects matching the domain ID.

### API Dependencies
- `GET /api/domains/[domainId]/questions`: Fetches the domain question list.
- `POST /api/questions/submit-solution`: Scores student responses.

### Database Dependencies
- `public.domains`, `public.subtopics`, `public.concepts`.
- `public.questions` (fetches core question details).
- `public.question_solutions` (saves solving attempts).
