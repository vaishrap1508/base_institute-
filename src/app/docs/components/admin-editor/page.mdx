# Admin Editor Components

This section outlines the authoring and previewing tools used by administrators and editors to manage, validate, and publish curriculum questions.

## Overview

This page provides an overview and technical specifications for the Admin Editor Components subsystem within the Kinetic Platform.

## 1. ContentEditor

A visual markdown WYSIWYG editor enabling styled stems, mathematical formula formatting, and student hint mappings.

### Purpose
To provide content authors with a rich text environment to draft and edit question prompts, utilizing custom bidirection sync converters.

### Location in Codebase
- File: [src/components/admin/ContentEditor.tsx](file:///Users/vaishu/Downloads/Base_Project/src/components/admin/ContentEditor.tsx)

### Props Interface
```typescript
interface ContentEditorProps {
  questionStem: string;                          // Active markdown question text.
  hintText: string;                              // Student prompt hint details.
  videoUrl: string;                              // YouTube explanation URL.
  onChangeQuestionStem: (text: string) => void;  // Callback dispatched on character edits.
  onChangeHintText: (text: string) => void;      // Callback dispatched on hint edits.
  onChangeVideoUrl: (url: string) => void;       // Callback dispatched on video URL change.
  onSaveDraft: () => void;                       // Saves the active question state as 'Draft'.
  onPublish: () => void;                         // Changes status to 'Published' and writes to database.
  isValid: boolean;                              // True if editor content satisfies publishing checks.
  validationErrors: string[];                    // Array of active warning strings.
}
```

### Formatting Converters (Markdown to HTML Sync)
To support contenteditable editing without losing raw markdown compatibility, the component implements sync parses:
- **`htmlToMarkdown(html: string)`**: Parses raw HTML elements and translates tags like `<strong>`, `<em>`, and `<code>` into `**`, `*`, and `` ` `` characters.
- **`markdownToHtml(md: string)`**: Translates markdown format symbols back to target inline HTML tags.

## 2. LivePreview

A device simulator displaying how the question will appear on client student dashboard frames.

### Purpose
Pre-renders styled questions, runs KaTeX mathematical pre-compiles, shuffles choices, and runs mock video player streams.

### Location in Codebase
- File: [src/components/admin/LivePreview.tsx](file:///Users/vaishu/Downloads/Base_Project/src/components/admin/LivePreview.tsx)

### State Management
- `deviceLayout` (`'desktop' | 'tablet' | 'mobile'`): Updates wrapper sizing classes (`w-full`, `w-[520px]`, `w-[340px]`).
- `selectedStudentChoice` (`string | null`): Simulates student choice clicks.
- `isVideoPlaying` (`boolean`): Initiates real embedded video streams inside a mock YouTube frame.
- `shuffleOrder` (`string[]`): Stores shuffled choice IDs.

### Mathematical Rendering via KaTeX
The nested component `SafeHtmlWithMath` splits output strings using block (`$$`) and inline (`$`) indicators:
- Submits formula segments to `katex.renderToString()`.
- Captures formatting exceptions and displays baseline plain code strings if compilation errors occur.

### Fisher-Yates Option Shuffling
To guarantee that options are shuffled without changing selection targets while editing:
- Calculates option hashes on load.
- Updates an array of shuffled keys (`shuffleOrder`).
- Keeps display structures aligned alphabetically (A, B, C, D) while shuffling option text blocks.

## 3. DomainSelectors

Provides cascading selectors that synchronize the placement of content within the educational hierarchy.

### Purpose
Ensures questions are correctly organized by Domain (e.g. Quant), Subtopic (e.g. Algebra), and Concept (e.g. Quadratic Equations).

### Location in Codebase
- File: [src/components/admin/DomainSelectors.tsx](file:///Users/vaishu/Downloads/Base_Project/src/components/admin/DomainSelectors.tsx)

### Props Interface
```typescript
interface DomainSelectorsProps {
  selectedDomain: string;                   // Selected domain ID.
  setSelectedDomain: (d: string) => void;   // Domain updates callback.
  selectedSubTopic: string;                 // Selected sub-topic ID.
  setSelectedSubTopic: (s: string) => void; // Sub-topic updates callback.
  selectedConcept: string;                  // Selected concept ID.
  setSelectedConcept: (c: string) => void;  // Concept updates callback.
}
```
