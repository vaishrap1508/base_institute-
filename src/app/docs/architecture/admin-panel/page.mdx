# Admin Panel Architecture

Technical design specs for the administrator's review console, domain hierarchy controls, and analytics telemetry charts.

---


## Purpose

The main purpose of this module is to ensure system responsiveness, coordinate client events, and maintain relational integrity across data stores.

## Overview
The Admin Panel is located under `/admin/*` routes and is restricted to users with the `ADMIN` role. It provides tools for approving creator submissions, configuring domain hierarchies, managing users, and tracking platform telemetry.

---

## Admin Workspaces

### 1. Question Approval Queue
- **Draft Reviews**: Lists newly submitted questions awaiting verification.
- **Formulas Previewer**: Automatically compiles LaTeX formulas inside options or descriptions to ensure they render correctly before publishing.

### 2. Domain Hierarchy Tree Editor
- **Tree-based Sequencing Map**: An interactive dashboard showing domains, subtopics, and concepts.
- **Drag-and-Drop Sequencing**: Updating course node sequencing (`seq_order`) propagates to the database, adjusting sorting orders on student roadmaps.

### 3. User Logs & Clearances Control
- **Authorization Reassignments**: Allows administrators to promote or suspend accounts, reset daily streaks, or modify roles.

---

## Analytics Telemetry & Cache
- **Key Metrics**: Tracks user growth, active sessions, and quiz completions.
- **Telemetry Charts**: Visualizes performance metrics using custom chart wrappers.
- **Postgres Cache Views**: Detailed statistics are cached in PostgreSQL materialized views to maintain fast, low-latency dashboard loads.

---

## Access Restrictions
> [!CAUTION]
> Admin routes are restricted at the Edge network layer inside `middleware.ts`. Requests targeting `/admin/*` from accounts without the `ADMIN` role are automatically blocked and redirected to the login page.

---

## Architecture

This component is integrated into the Next.js and Supabase tier, responding dynamically to API endpoints and schema constraints.
