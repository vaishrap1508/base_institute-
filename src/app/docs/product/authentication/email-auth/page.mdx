# Email & Password Authentication

Technical documentation for the credentials-based signup, login, and password recovery workflows.

---


## Overview

This page provides an overview and technical specifications for the Email & Password Authentication subsystem within the Kinetic Platform.

## Purpose
Email & Password Authentication provides account control for users who prefer standard credential logins. It processes signup requests, verifies emails, and handles account recovery workflows.

---

## Registration and Sign-Up Flow
- **Registration Form**: The user submits their email, password, and full name.
- **Supabase Call**: The client triggers `supabase.auth.signUp({ email, password, options: { data: { full_name } } })`.
- **Database Entry**: Supabase inserts a row into `auth.users`, which triggers `handle_new_user()` to create their profile in `public.profiles`.
- **Verification Email**: Supabase sends a verification email. The account remains locked until the user verifies their email.

---

## Session Lifecycle Management
- **Cookies**: Auth state is saved in the browser using secure cookie formats.
- **Refresh Flow**: Next.js middleware automatically uses the `refresh_token` to renew active user sessions before they expire.

---

## Password Reset Flow
1. **Request**: The user requests a password reset, dispathing a tokenized link via `/api/auth/forgot-password`.
2. **Redirect**: Clicking the link redirects the user to `/auth/reset-password`, allowing them to submit a new password safely.
3. **Execution**: The client calls `supabase.auth.updateUser({ password: newPassword })` to update the password in the database.

---

## Error Handling
The authentication flow catches and displays descriptive error messages:
- `Invalid login credentials`: Checked if email or password does not match.
- `Email not confirmed`: Displayed if the student attempts login before clicking their verification link.
- `Rate limit exceeded`: Triggers if the client makes too many login attempts in a short period.

> [!CAUTION]
> Session cookies use `HttpOnly`, `Secure`, and `SameSite=Lax` configurations to prevent cross-site scripting (XSS) token extraction.

---

## Architecture

This component is integrated into the Next.js and Supabase tier, responding dynamically to API endpoints and schema constraints.
