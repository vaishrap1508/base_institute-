# Leaderboard

The community-wide ranking system, displaying user ranks, earned points, and active study streaks.

---


## Purpose

The main purpose of this module is to ensure system responsiveness, coordinate client events, and maintain relational integrity across data stores.

## Overview & Purpose
The Leaderboard introduces friendly competition to keep students motivated. Ranks are based on weekly, monthly, and all-time Experience Points (XP) earned from completing lessons, practice questions, and mock exams.

---

## Key Features

### 1. Multi-Dimensional Ranks
- **Global Rankings**: Ranks all registered platform candidates.
- **Friends Filter**: Filters rankings to show only connected peers, removing college filters.
- **Weekly Reset**: Resets weekly rankings every Sunday at 00:00 UTC to maintain active competition.

### 2. Live Performance Badges
- Highlights earned milestone badges (such as "🌱 First Step" or "👑 On Track") directly next to candidate names in ranking lists.

---

## Technical Performance Optimization
- **Cached Ranks**: To prevent database bottlenecks with 200,000+ active users, rankings are cached in a PostgreSQL materialized view (`landing_stats_cache`) and updated once an hour.

---

## Database Schema
- **`public.profiles`**: Queries `id`, `full_name`, and total accumulated XP.
- **`public.user_streaks`**: Displays the active streak counts for each candidate.

---

## Architecture

This component is integrated into the Next.js and Supabase tier, responding dynamically to API endpoints and schema constraints.
